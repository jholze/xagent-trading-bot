## Rev 1 measurement (this head)

The clock starts immediately before `trade_ctx_fields` + `_place_reduce_only_stop` and stops immediately after the reduce-only stop `create_order`. Fake exchange. The order-path client sleeps 20 ms inside `GET` so the after sample can show that read inside the bracket. The in-process cache holds `RISK_ON`; the after read returns `RISK_OFF` from the GET body.

Local run, 2026-11-10, 15 samples each:

| check | before | after |
| --- | --- | --- |
| what is timed | stop write, decision-time state already set | same stop write, no decision-time state |
| order-path GETs inside the bracket | 0 | 15 (one per write) |
| p95 | 5.998 ms | 25.535 ms |
| reduce-only stop `create_order` inside the bracket | yes | yes |
| cache used as the read | no | no (`RISK_OFF` from the GET, cache was `RISK_ON`) |

The 20 ms sleep is a test probe, not a product budget. Issue #765 does not set a p95 millisecond target. These two p95 figures are this machine's samples, not a claim about production Redis.
