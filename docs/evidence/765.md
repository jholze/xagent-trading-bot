# Evidence #765: order-path Redis read is bounded and fail-closed

The synchronous oracle read on an entry (`get_order_path_redis_snapshot`) no longer uses the in-process snapshot as a fallback. A socket timeout raises `OracleReadTimeout`. A BUY or SHORT is not sent. A SELL is not blocked by that timeout.

RECALL_FAILED (Hindsight at `http://127.0.0.1:8888` was not reachable).

Measured locally against Redis on `127.0.0.1:6379`, 200 GETs, reused client. Numbers are also printed by `test_measured_redis_get_p95_and_p99`.

| check | before | after |
| --- | --- | --- |
| read on the order path | `get_latest_snapshot` (memory cache, then Redis, errors become None) | Redis GET only; timeout raises; cache is not a fallback |
| p95 of 200 GETs on `127.0.0.1:6379` | not measured | 0.045 ms (acceptance < 50 ms) |
| p99 of 200 GETs on `127.0.0.1:6379` | not measured | 0.050 ms (acceptance < 200 ms) |
| timeout while cache holds `RISK_ON` | order proceeds with None or the cache | `OracleReadTimeout`; BUY is not sent |
| SELL on the same timeout | proceeds | still proceeds |
