# Evidence: risk fail-closed default `deny` (#754)

## Change

`_fail_closed_guards_mode` (`risk/risk_manager.py`) returns `log` only for an explicit string `"log"` (case- and whitespace-insensitive). Anything else is `deny`: a `None` config, a missing `risk` block, a missing key, `None`, an empty or unknown value, a non-string value, or an exception while reading the config. Before, every one of those cases was `log`, which is fail-open.

## Runtime effect

- Staging `config.json` already has `"fail_closed_guards": "deny"`, so the staging paper bot does not change.
- `main` `config.json` has no key. Rolling this out to live would switch live from `log` to `deny`. A raising guard would deny the order (`<guard>_error`), and degraded market bias would block new non-DCA entries (`market_bias_degraded`). That rollout is Jens' decision. To keep live on `log`, set the key explicitly first.
