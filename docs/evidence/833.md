## Semantics to confirm (owner)

- **#832 wording superseded.** The issue text says "deferred and counted in `stale_tagged_short_deferred`". The frozen #826 behaviour table and the #809 contract say that a tagged lot at a `stale` cycle quote gets the unpriced cover (`COVER price stale…`). The cycle path is the stale backstop, because the hub skips stale ticks and leaves the cover to the cycle. #832 is therefore implemented as "stale-price flag carried into the aria_bot queue-off path". Queue on and queue off now make the same decision. The hub's `stale_tagged_short_deferred` stat is unchanged. The round-0 deferral helper and its process-wide counter are removed.
- **Read-intent proof.** A recovery read places no risk, so it does not set margin. The read proof is: adapter mode and resolved execution mode are both `testnet`, and ccxt `isSandboxModeEnabled is True`.
- **Freshness is a local-stamp check.** Set and readback are stamped with this host's clock when each response arrives, and `observed_at` is taken after both. The Gate position payload has no server time, so no server-time skew is measured and `clock_skew_seconds` is not applied. The proof is not re-checked between the route check and `create_order`.
