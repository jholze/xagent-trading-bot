## Change (`services/mcp/nav.py`, read-only, display only)
- Epoch start = newest `ledger_epoch.started_at` marker in the trade_history docs (:demo/:live), else newest `ledger_epochs` doc of the tenant (new `load_epoch_readonly`, `find()` only, only `epoch_id`/`started_at` leave the loader).
- A daily NAV point belongs to the epoch when its `as_of` is at/after the start (today's point is overwritten each cycle); without `as_of`, day > start day.
- `peak_nav`, `current_drawdown_pct`, `max_drawdown_pct`, `nav_points`, `first_date` count only epoch points, initial capital of the epoch, and trade_history HWMs whose `peak_equity_at` is at/after the start.
- New `ledger_epoch` field and `pre_epoch` block (peak_nav, max_drawdown_pct, initial_capital, last_nav, nav_points, first/last date, trade_history peaks set before the epoch). Curve rows carry `epoch: pre|current`; running peak restarts at the epoch.
- No epoch found -> old behaviour unchanged.
- Expected after deploy: henry peak 100,075.37 (trade_history_live), dd ~0.08 %; default peak 101,542.16, dd ~1.0 %.

## `peak_equity_by_scope.live` on paper tenants: not a bug
Staging `config.json` runs `trading_mode: live` + `live.dry_run: true` (shadow = live dry-run). For that mode `services/portfolio_nav_history.persist_peak_equity` writes the HWM through `_trade_history_io()` into `<tenant>:live`, and `RiskManager` (`_rule_switch_drawdown_pct`, drawdown throttle) reads it from `load_live_trade_history()`. NAV points land in ledger scope `demo`. So `:live` is the active HWM the risk throttle uses; `:demo` stays at the reset value 100,000 (peak_equity_at = epoch start). Both values are post-epoch (live 15:14/15:19 UTC on 11-04). No code change there; the tool notes now say it. Scope mismatch flag stays.
