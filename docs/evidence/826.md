## Route guard notes

- `NoRedirectSession` (a `requests.Session`) sets `follows_redirects = False` and `max_redirects = 0`, and forces `allow_redirects=False` on every request. With `strict_route` on, the adapter swaps the ccxt session for it, so later order calls cannot follow a redirect either. Test: a 302 comes back after one send. A plain session follows the redirect.
- No production `ModeProof` producer exists yet. `collect_mode_proof` needs a set record and a readback, and both are transport calls. Testnet also signs with the live `api_key_env` name. So with `strict_route: true`, production denies with `mode_proof_missing`, and then `testnet_env_aliases_live`, before any call. That is fail-closed. Committed config has no `strict_route` and `testnet_futures.enabled=false`, so paper is unchanged.

```
short_cover tagged <SYM> halt=<bool|None> stale=<bool> timeout=<bool> sched=<set|none> -> <source> (<rationale>)
```

- Route guard: search `futures testnet route denied`. It appears only when `strict_route` is literally true.
