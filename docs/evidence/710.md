# Evidence #710: exit-radar WS robustness (reconnect watchdog, stale-price guard, real ATR)

Paper only (staging). Release framework rule 5: an evidenced and tested bug fix. No backtest and no new trial (nothing registered in `backtest/harness/trials.py`).

## Problem (issue #710, paper log of 15.10.2026)

- The Gate spot WS dropped every 10 to 14 minutes. Between 04:23 and 06:16 MESZ no stop fired for HBAR, even though the price crossed the stop level.
- Three gaps in `services/exit_realtime/hub.py`:
  1. **Backoff never reset.** It grew by ×1.5 per reconnect up to 60 s and stayed there. After a few drops, every reconnect waited 60 s, with no prices during that time.
  2. **No silence detection.** A half-open socket (TCP alive, no frames) was only noticed by the protocol ping. If Gate stopped pushing one pair (subscription lost server-side), nothing noticed at all.
  3. **No stale-price guard.** A late or replayed frame was evaluated as if it were the current price.
- Separately, the WS book row used a flat `atr_reference_pct` (3.0) for every lot. The decision cycle uses the live ATR of the coin, so the WS trail ran with a different distance than the cycle.

## Before / after

| Case | before | after |
|---|---|---|
| Drop after a 12 min connection | wait = previous backoff (up to 60 s) | wait = base (3 s): a connection that held ≥ `stable_connection_sec` (60 s) resets the backoff |
| Flapping (< 60 s per connection) | ×1.5 up to 60 s | unchanged (×1.5 up to 60 s) |
| Protocol keepalive | `ping_interval=20`, no timeout | `ping_interval=20, ping_timeout=10` plus an app-level `spot.ping` every 15 s |
| No tick on any pair for 90 s while connected | stays "connected" with no prices | watchdog forces a close, and the normal reconnect loop resubscribes everything (`watchdog_reconnects`) |
| One open-lot pair silent for 300 s while others tick | never noticed | that pair is resubscribed, rate-limited per pair (`watchdog_resubscribes`) |
| Tick with `time_ms` older than 30 s | evaluated | skipped, debounced WARNING `ws_stale_tick_skip`, counter `ws_stale_tick_skip`; the next fresh tick is evaluated |
| Tick without `time_ms` (result and envelope) | evaluated | evaluated (no change; envelope `time_ms` is now used when the result has none) |
| WS row ATR | `atr_reference_pct` or 3.0 | live ATR(14)% of symbol/timeframe from the book-refresh thread, cached 900 s, max 10 REST fetches per refresh; on any failure, or < 15 candles, falls back to the reference (`atr_source` = live / cached / reference) |
| Reconnect log | none | `exit_realtime ws connected: down_for=… subscribed=… failed=…` |

All knobs are `exit_realtime.*` settings with the defaults above: `max_tick_age_sec`, `watchdog_interval_sec`, `app_ping_sec`, `silent_reconnect_sec`, `stale_resubscribe_sec`, `stable_connection_sec`, `live_atr`, `atr_ttl_sec`, `atr_fetch_max_per_refresh`. 0 switches the stale guard off. This PR changes no tenant config.
