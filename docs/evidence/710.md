# Evidence #710: exit-radar WS robustness (reconnect watchdog, stale-price guard, real ATR)

Paper only (staging). Release framework rule 5: an evidenced and tested bug fix. No backtest and no new trial (nothing registered in `backtest/harness/trials.py`).

## Problem (issue #710, paper log of 15.10.2026)

- The Gate spot WS dropped every 10 to 14 minutes. Between 04:23 and 06:16 MESZ no stop fired for HBAR, even though the price crossed the stop level.
- Three gaps in `services/exit_realtime/hub.py`:
  1. **Backoff never reset.** It grew by ×1.5 per reconnect up to 60 s and stayed there. After a few drops, every reconnect waited 60 s, with no prices during that time.
  2. **No silence detection.** A half-open socket (TCP alive, no frames) was only noticed by the protocol ping. If Gate stopped pushing one pair (subscription lost server-side), nothing noticed at all.
  3. **No stale-price guard.** A late or replayed frame was evaluated as if it were the current price.
- Separately, the WS book row used a flat `atr_reference_pct` (3.0) for every lot. The decision cycle uses the live ATR of the coin, so the WS trail ran with a different distance than the cycle.

## Before / after

| Case | before | after |
|---|---|---|
| Drop after a 12 min connection | wait = previous backoff (up to 60 s) | wait = base (3 s): a connection that held ≥ `stable_connection_sec` (60 s) resets the backoff |
| Flapping (< 60 s per connection) | ×1.5 up to 60 s | unchanged (×1.5 up to 60 s) |
| Protocol keepalive | `ping_interval=20`, no timeout | `ping_interval=20`, no protocol timeout (opt-in `ws_ping_timeout_sec`), plus an app-level `spot.ping` every 15 s. The first version had `ping_timeout=10`; on staging it dropped the Gate WS every ~37 s (`ping/pong timed out`, 04.11. 21:57–21:58 MEZ), fixed in the follow-up PR |
| No tick on any pair for 90 s while connected (also when every subscribe failed) | stays "connected" with no prices | watchdog forces a close, and the normal reconnect loop resubscribes everything (`watchdog_reconnects`); at most one forced reconnect per 300 s (`forced_reconnect_min_gap_sec`) |
| One open-lot pair silent for 300 s while others tick | never noticed | that pair is resubscribed, rate-limited per pair (`watchdog_resubscribes`) |
| Tick more than 30 s later than the connection's minimum lag (skew-corrected: `raw age − min(raw age)` on this connection) | evaluated | skipped, debounced WARNING `ws_stale_tick_skip`, counter `ws_stale_tick_skip`; the next fresh tick is evaluated |
| Host clock ahead of / behind Gate | — | absorbed by the minimum-lag baseline, so ticks are never muted by skew alone (fail-open) |
| Tick without `time_ms` (result and envelope) | evaluated | evaluated (no change; envelope `time_ms` is now used when the result has none) |
| WS row ATR | `atr_reference_pct` or 3.0 | live ATR(14)% of symbol/timeframe from the book-refresh thread, cached 900 s, max 10 REST fetches per refresh; on any failure, or < 15 candles, falls back to the reference (`atr_source` = live / cached / stale_cached / reference; ATR% is taken against the last candle close, so the cache is tenant-independent) |
| Reconnect log | none | `exit_realtime ws connected: down_for=… subscribed=… failed=…` |

All knobs are `exit_realtime.*` settings with the defaults above: `max_tick_age_sec`, `forced_reconnect_min_gap_sec`, `watchdog_interval_sec`, `app_ping_sec`, `silent_reconnect_sec`, `stale_resubscribe_sec`, `stable_connection_sec`, `live_atr`, `atr_ttl_sec`, `atr_fetch_max_per_refresh`. 0 switches the stale guard off. This PR changes no tenant config.

## DeepSeek follow-up (same session, head 4f29a991): APPROVE WITH NITS

- Blocker confirmed resolved by tracing the `_run_loop` integration test.
- Fixed: a stale tick no longer refreshes the watchdog clocks (`_last_any_tick`, `_pair_last_tick`), so a stream that only delivers late frames still triggers the silent-stream reconnect (test `test_stale_ticks_do_not_keep_the_watchdog_quiet`). Docstring of `resolve_row_atr` lists `stale_cached`.
- Known and accepted: the guard is relative to the minimum lag on the connection, so an ordered backlog that is uniformly old passes it (weaker than an absolute 30 s check). Accepted because skew must never mute stops; the watchdog covers drops and Gate sends a snapshot on resubscribe.
- Left as is: `app.close()` under `_ws_send_lock` could block on a hung socket; websocket-client closes with its own timeout. Listed for the Opus review.
