# Evidence: cycle silence and the auto-order watchdog

Money-path change. This branch is stacked on #738, so the diff against `staging` includes the hard-stop full sell as well as the cycle-silence fix. The owner decides. This file does not add `owner-approved`.

A held lot that is already through the hard stop gets one `source=auto` stop from the cycle merge, instead of the entry queue replacing that check with HOLD. Heartbeat jobs are kept when the queue is trimmed. The watchdog alarms when a tenant has no `source=auto` order for N cycles. N is not a literal in code. `config.json` sets `observability.cycle_watchdog.auto_silent_cycles` and `fill_silent_cycles` to 60 (`ceil(7200 / update_interval 120)`). A tenant body can override both. Missing or invalid N raises one `watchdog_unconfigured` alarm and does not guess. 60 cycles is at least two hours, because a real cycle can run longer than 120 seconds.

## Review fixes (code review 2026-11-01)

1. `bus/eval_queue._trim_queue`: the old code ran `ZREVRANGE 0 -1` over the whole queue, then did one HGET and one ZREM per member on every over-cap enqueue. It never deleted the trimmed members' meta. Now the worst end is read in chunks (64, then doubling), with one ZREVRANGE plus one HMGET per chunk, and the scan stops once enough victims are found. Victims are removed with one ZREM, and their meta with one HDEL. When only protected heartbeats remain above the cap, scans pause for 30 s, and the warning is logged at most once per 60 s. The queue is still trimmed exactly to `max_len`, and heartbeats are still never trimmed.
2. `strategies/decision_engine.py`: the merge hard-stop flag lived on the shared `DecisionEngine` instance as `self._merge_long_hard_stop`. It is now a per-evaluation `merge_flags` dict, created in `_evaluate_internal` and passed to `_merge_sell(merge_flags=...)`. The 6-tuple return is unchanged.
