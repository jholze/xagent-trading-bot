# Evidence: unique Mongo DB per test for the flaky ledger backend tests (#752)

This change is test-only. No production code is changed.

## Cause

`test_buy_sell_cycle_equivalent_results` and `test_local_vs_mongo_buy_sell_snapshots_match` in `tests/unit/test_mongo_backend.py` used one shared DB name. So did the fixture in `tests/integration/test_demo_mongo_runtime.py`. When two pytest processes hit the same mongod (CI retries, or several worktrees on the shared box), one process's setup or cleanup dropped or overwrote the other process's ledger rows.

## Fix

Each of these tests now uses its own DB: `<resolve_test_db_name()>_<uuid12>`. The test resets the cached client so the new name takes effect, and a finalizer drops the DB afterwards.

## Before / After

Stress test: 3 pytest processes ran at the same time, 15 iterations each of the two backend tests, against one local mongod.

| process | before | after |
| --- | --- | --- |
| 1 | 15/15 failed | 0/15 failed |
| 2 | 14/15 failed | 0/15 failed |
| 3 | 12/15 failed | 0/15 failed |

Before is staging 73b1aa8f; after is this branch.

Local full unit suite on this branch: 6301 passed, 6 skipped, 1 xfailed. Ruff (E9, F821, F823) is clean on the changed files.
