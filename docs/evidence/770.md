# PR #770 – /plan restarts with the current ledger epoch

## Bug (vs. spec)
Spec (Jens, 2026-11-04): a ledger reset must restart "Plan vs. Portfolio (365 Tage)".
Observed on staging after reset `e20261104T095950Z` (2026-11-04 09:59:50 UTC = 10:59 Berlin):
`Plan-Start 2026-07-28 · Tag 99/365 · Plan heute $163,848 · Δ -38.8% · BTC HODL seit 2026-09-07 · Kennzahlen 7d` over pre-reset trades.

Root causes
1. `config.json` `portfolio_plan.plan_start_date = "2026-07-28"` (hard-coded in 245a3ed3 after the July reset); `resolve_plan_start_date` returns it first.
2. BTC HODL baseline = first `portfolio_nav_daily` row with `btc_close` (2026-09-07); the reset keeps `portfolio_nav_daily` by design.
3. KPIs read `orders_v2` (kept by the reset) for 7 days without an epoch cut.
4. Start capital came from the snapshot, not from the epoch.

## Known limits
- HODL baseline is the `btc_close` of the first NAV point written after the reset (reset day's point, overwritten each cycle), not the exact BTC price at 09:59:50 UTC. Until day 2 BTC shows +0.0 %. Good enough for daily granularity; exact price at reset would need the reset tool to store `btc_close` in the epoch marker (follow-up).
- Morning briefing 7d KPIs are not epoch-cut yet (default `since=None`); follow-up.
