### Honest caveats

- **In-sample package.** T+G+V+E was assembled after the single-rule results were seen. The DSR deflates for 65 trials, but the choice of the combination is still in-sample. Treat henry GO as "worth a paper run", not proof.
- The harness does not simulate max open positions or one lot per coin. The `limits` block (2,500 USDT/buy, 20 positions, 8 %/coin, 1 lot/coin, brake −12 %) is part of the plan but was **not** backtested together with T+G+V+E.
- The plan mentions oracle-dependent no-chase limits (10/15/20 %); this PR implements the fixed 15 % that was tested.
- Missing or gapped candle data keeps the entry (same as the harness), so a data outage weakens T/G instead of blocking buys.
- default stays the comparison tenant without switches (verdict OBSERVE).

```json
    "limits": {
      "enabled": true,
      "max_usdt_per_order": 2500,
      "max_open_positions": 20,
      "max_position_pct": 8,
      "max_lots_per_coin": 1,
      "drawdown_brake_pct": 12
    }
  },
  "max_usdt_per_trade": 2500,
  "risk": {"moderate_deploy": {"enabled": false}}
}
```

- The `rule_switches.limits` values are hard caps on top of the existing keys (tighter one wins), so the oracle-adjusted `max_open_positions` (16–44) cannot exceed 20 and `max_position_percent` 30 cannot exceed 8 %.
- `max_usdt_per_trade: 2500` and `risk.moderate_deploy.enabled: false` implement the plan's "2,500 USDT per buy, boost 1.0×". They are existing keys; leave them out if only the new switches should change.
- `include_locked: false` keeps owner locks absolute. Set `true` only if rule E should also close locked lots.
- Rollback: set `rule_switches.<rule>.enabled` to `false` (or remove the block). No restart of other tenants needed.
