# Evidence: unique Gate clientOrderId for long autoshort keys (#753)

## Cause

Gate allows at most 26 payload bytes in a clientOrderId (`t-` prefix, charset `[0-9A-Za-z_.-]`). `_clamp_gate_client_order_id` cut every longer key to its first 26 sanitised characters. Autoshort keys (`autoshort|SYMBOL/USDT|tf|strategy|price`) differ only at the end, so two entries on the same symbol got the same coid. `climaxfade|SYM|4h|ts` had the same problem. Startup recovery matches open orders by coid, so a new entry could match an older order.

## Fix

- Over-long keys that are not pure hex now become `head[:11] + "." + sha256(raw)[:14]`. That is 26 characters, deterministic, and inside the charset.
- Over-long pure-hex keys (UUIDs) keep the old 26-character cut. Short keys are unchanged.
- Recovery stays strictly ID-based. No time filter was added, because one could cause a double order.
