## Problem

`replay_simulated_ledger` counted only `filled` rows, and every production caller dropped every other status before calling it. A remainder-canceled buy reloaded as no lot, and its quote never entered simulated cash.

## Opus fix (2026-11-11)

| Finding | Change |
| --- | --- |
| HIGH: callers pre-filtered to `filled` | `row_counts_for_replay` is the filter in `services/ledger_sync.py`, `data_manager.py` (cash, realized PnL, history reconcile), `notifications/daily_portfolio.py`, and `notifications/telegram_commands/position_display.py` |
| MEDIUM: filled rows that share an exchange id collapsed | Dedup runs only for an identity that has a partial or canceled row. Two filled rows with different ids and one exchange id both count |
| MEDIUM: tie-break and side were untested | Same timestamp keeps the larger execution amount, then the later row. A buy and a sell that share an id both apply |
| LOW: unpriced partial sell reduced the lot for zero cash | That sell is skipped and logged. The lot stays |
| LOW: evidence name failed review-gates | This file is `docs/evidence/659.md` |

Reload test: `_build_positions_snapshot_from_orders` on a remainder-canceled buy of 40 coins / 40.08 USDT keeps amount 40 and average 40.08/40. A rejected row in the same list does not.

Cash test: `resolve_sim_cash_balance` on that order returns initial capital minus 40.08. `compute_sim_cash_from_orders` on the same row matches.
