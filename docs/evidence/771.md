# Evidence: sniper memory score sign (#771)

Money path: `services/dca_sniper/`, `strategies/`. Bug fix under release framework rule 5 (bug evidenced, tested). Not a strategy trial; the trial register (#769) is not incremented. If this change is later replayed in the harness, that replay counts as one trial (P7 in the 04.11. chain analysis).

## The bug

`services/dca_sniper/checklist.py` (staging `1d2a041f`), memory layer:

```
mem = 2.0 + min(1.5, 0.4 * rag_hits) + min(1.0, 0.25 * dca_lesson_count)
```

Both terms are always positive. The lessons are written by `strategies/dca_reflector.py` (rules at lines 161/179/236/260) and `intelligence/memory/reflector.py` (55/62). Most of them are warnings. Example from the 31.10. tenant logs: `dca_lessons=1(DOGE/USDT: DCA policy skipped add-ons often …)`. That warning raised the score.

## Before / after

| case | before | after |
| --- | --- | --- |
| 1 warning lesson + 1 warning RAG hit | 2.65 | 1.10 |
| 4 warning lessons, no RAG | 3.00 | 0.50 |
| 1 confirming lesson ("often green") | 2.25 | 2.25 |
| lesson of unknown direction | +0.25 | 0 |
| mean memory bonus per symbol (77 symbols) | +0.27 | −0.52 |
| full unit suite | green on staging | 6741 passed, 6 skipped, 1 xfailed |

Effect on the total score: the memory layer has weight 1.0 of 10.2 and the total is normalised ×2, so Δtotal ≈ 0.196 · Δmemory. With `heavy_min_score` 6.5 the change is modest: a symbol loses about 0.15–0.5 total points when memory warns. It cannot add more than before (positive caps are equal or lower).
