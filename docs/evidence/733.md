# Evidence: DCA grace and the stop-resolver gap

Money-path change (DCA partial stop and full stop). The owner decides. This file does not add `owner-approved`.

Grace delays only the partial. The default window is 12 hours (`_DEFAULT_GRACE_HOURS`). The full stop still fires inside that window, from `average_entry`, on the cycle and the WebSocket path. After the window, open DCA rounds no longer keep the partial paused. `config.json` and the #719 resolvers are unchanged: strategy and risk still disagree, and the tests lock that table.

Staging's new safety pins disagreed with this spec. `test_partial_stop_paused_during_dca` asserted a pause for `{dca_rounds: 1, last_dca_at: None}` and got False. `test_partial_stop_stays_paused_while_rounds_remain_if_flag_off` asserted a pause for open rounds with the flag off and no timestamp, and got False. #722 names that change: a missing timestamp is outside grace, and open rounds do not keep the partial paused once the window has passed. The pins now expect a pause only while the timestamp is inside the 12-hour window. `docs/domain/prevention-rules.md` on this branch says the same.
